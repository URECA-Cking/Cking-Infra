# AWS 예산

> 전제: AWS Budgets `cking-monthly`(콘솔 관리), 월 $150, 2개월 비용 상한 50만원(월 약 $175)

실제 비용이 월 $150의 85%($127.5)·100%에 닿거나, 월말 예측이 100%를 넘을 때 메일.

## 뜻하는 것

평소보다 돈이 나가고 있다. 비용은 팀 대표가 사후 결제한다. 정상 사용은 월 약 $91이고, NAT Gateway(월 약 $43) 같은 실수 하나를 더하면 85% 알림선을 넘는다.

## 먼저 볼 곳

1. Billing → Cost Explorer: 서비스별, 일별로 언제부터 무엇이 늘었는지
2. 사용 유형(Usage type)으로 좁힌다: 인스턴스 시간, 데이터 전송, 스냅샷

## 원인별 대응

- **부하 테스트 환경이 남아 있음**: `envs/loadtest`에서 `terraform state list`가 비어 있지 않으면 측정 뒤 지우지 않은 것이다. `terraform destroy`
- **NAT Gateway, RDS 다중 AZ, 큰 인스턴스**: 콘솔에서 만든 리소스를 확인하고 지운다·되돌린다
- **CloudFront·WAF·데이터 전송**: 요청이 갑자기 늘었는지 CloudFront 보고서를 본다
- **EBS 스냅샷**: 관측 서버 스냅샷은 DLM이 관리한다. 수동 스냅샷이 쌓였는지 본다
- 원인이 정상 사용 증가면 예산과 상한을 팀과 다시 정한다

## 하면 안 되는 것

- 원인을 모른 채 리소스를 지우지 않는다. 특히 RDS·관측 서버 데이터 디스크(`prevent_destroy`)
