# 댓글 판정 대기열 쌓임

> 전제: [댓글 필터 차단·해제](comment-filter.md)의 전제와 같다. 판정 스레드 2개, 대기열 100

판정 대기열(`executor_queued_tasks{name="commentFilterExecutor"}`)이 50건 이상인 상태가 5분 이어질 때(Prometheus).

## 뜻하는 것

들어오는 판정이 처리량보다 많거나, 필터 호출이 오래 걸려 판정 스레드 2개가 묶였다. 대기열이 100건을 넘으면 새 댓글은 PENDING으로 남고 재필터링이 처리한다. 댓글은 보이고 판정만 늦어진다. 평소에는 0건이고, 정상 처리량은 분당 150건 이상이다(판정 0.1~0.8초, 스레드 2개). 필터를 켤 때 쌓여 있던 판정을 처리하며 최대 17건까지 찼다가 몇 초 안에 비었다(2026-10-21 개발).

## 먼저 볼 곳

[판정 상태 보기](comment-filter.md#판정-상태-보기)에서 처리 중인 스레드(`executor_active_threads`), BE가 필터 응답을 기다린 시간, 판정·실패 로그를 본다.

## 원인별 대응

- **필터 호출이 묶임**(처리 중 스레드 2, 대기 시간이 길거나 `TIMEOUT`이 이어짐): 필터가 응답하지 않는 상태다. [즉시 차단](comment-filter.md#즉시-차단해제)으로 호출을 바로 실패시켜 스레드를 풀고, [호출 실패 지속](cking-comment-filter-failing.md)과 같이 원인을 본다
- **댓글이 한꺼번에 많이 들어옴**(대기 시간은 평소와 같음): 기다린다. 넘친 댓글은 재필터링이 분당 최대 20건씩 다시 제출한다

## 해결 확인

`executor_queued_tasks{name="commentFilterExecutor"}`가 0으로 돌아온다.

## 하면 안 되는 것

- 판정 스레드 수를 늘려 대기열을 비우려 하지 않는다. 필터가 응답하지 않는 상태면 묶이는 스레드만 늘고, Lambda 동시 실행도 그만큼 늘어난다

## 운영에서 다른 점

- 서버별 대기열의 최댓값으로 본다. 함수 이름은 `prod-cking-comment-filter`다
