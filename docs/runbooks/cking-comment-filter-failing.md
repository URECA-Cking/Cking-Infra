# 댓글 필터 호출 실패 지속

> 전제: [댓글 필터 차단·해제](comment-filter.md)의 전제와 같다. 응답 대기 30초

10분 안에 앱 로그 `필터 서비스 호출에 실패했습니다`가 5건 이상일 때(Loki).

## 뜻하는 것

BE가 필터 Lambda를 불렀지만 판정을 받지 못했다. 실패한 댓글은 보이는 상태로 남고 재필터링이 1·2·4·8분 간격으로 다시 요청한다. 판정이 늦어지는 동안 차단돼야 할 댓글도 보인다. 평소에는 0건이다. 콜드 스타트(6\~17초)는 응답 대기 30초 안에 끝나고, 드물게 느린 콜드 스타트(53.5초)도 그때 처리 중이던 1\~2건만 실패한다.

재시도를 5번 다 쓴 댓글과 인증 거부·요청 거절(4xx)은 ERROR 로그를 남겨 [ERROR 로그](cking-error-log.md) 경보가 따로 울린다.

## 먼저 볼 곳

[판정 상태 보기](comment-filter.md#판정-상태-보기)의 판정·실패 로그에서 `failureKind`를 본다.

## 원인별 대응

- `TIMEOUT`: 30초 안에 응답이 없다. [콜드 스타트 확인](comment-filter.md#콜드-스타트-확인)에서 `Status: timeout`이나 긴 `Duration`을 본다. 새 이미지 배포 직후 콜드 스타트면 몇 분 안에 풀린다
- `SERVER_ERROR`: Lambda가 5xx를 돌려줬다. Lambda 로그의 오류를 본다
- `THROTTLED`(429): 즉시 차단(예약 동시성 0) 중이면 예상된 경보다. 차단하지 않았다면 계정 동시 실행 한도에 걸린 것이다
- `NETWORK`: 연결하지 못했다. 함수 URL 주소(`COMMENT_FILTER_BASE_URL`)와 앱 서버의 바깥 연결을 본다

필터가 계속 실패하고 잘못된 판정이 걱정되면 [즉시 차단](comment-filter.md#즉시-차단해제)한다.

## 하면 안 되는 것

- 실패를 줄이려고 응답 대기(30초)를 줄이지 않는다. 콜드 스타트를 기다리지 못해 실패가 늘어난다

## 운영에서 다른 점

- 운영 앱 서버 전체 로그를 합쳐 센다. 함수 이름은 `prod-cking-comment-filter`다
